## 1. Developer Portal and the Bluebeam Studio API: what exists, how to authenticate, limits, sandbox, approval, cost, and whether a browser SPA with a serverless backend can use it

### Takeaway
There is one public REST API — the **Bluebeam Studio API** (Sessions, Projects, Project-file Jobs, Session Markups, Webhooks/Subscriptions, Users) — reached through five regional hosts and secured with OAuth 2.0 authorization-code + refresh-token using a client secret. Portal access is self-service for holders of a Core, Complete or Max plan; apps start in a single-user Sandbox and need Bluebeam's written production approval before other users can sign in. Numeric rate limits and any API fees are not published on any page reachable without login.

**Session lifecycle details**
- Create Session body: `Name` (required), `Notification`, `Restricted` (true = only invited/added emails; false = anyone with the 9-digit Session ID), `SessionEndDate` (UTC), `DefaultPermissions[]` with `Type` ∈ SaveCopy, PrintCopy, Markup, AddDocuments, FullControl, MarkupAlert and `Allow` ∈ Allow, Deny, Default. "When using the Bluebeam API to set permissions, 'Deny' is the default value." Response: `{"Id": "123-456-789"}`. — [Studio Session Guide](https://support.bluebeam.com/developer/studio-session-guide.html)
- "Be sure to include client_id in the header of your request." (examples send `Authorization: Bearer ...` plus a `client_id:` header). — [Studio Session Guide](https://support.bluebeam.com/developer/studio-session-guide.html)
- Adding a PDF is three steps: (1) `POST .../sessions/{sessionId}/files` with `Name` (must end ".pdf"), `Source`, optional `Size`/`CRC` → returns `Id`, `UploadUrl`, `UploadContentType`; (2) `PUT` the file to `UploadUrl` ("this will be directly to AWS") with headers `x-amz-server-side-encryption: AES256` and `Content-Type: application/pdf`; "Upload URL is valid for 10 minutes to start upload"; (3) `POST .../files/{id}/confirm-upload` (204 on success). — [Studio Session Guide](https://support.bluebeam.com/developer/studio-session-guide.html)
- "Studio Sessions do not support PDF/A files." — [Studio Session Guide](https://support.bluebeam.com/developer/studio-session-guide.html)
- Invite (`POST .../invite`, body `Email`, optional `Message`) emails the person and lets them create a free Studio account; Add user (`POST .../users`, body `Email`, `SendEmail`, optional `Message`) adds an existing Studio account without opt-in. The API caller automatically becomes Host. — [Studio Session Guide](https://support.bluebeam.com/developer/studio-session-guide.html)
- Session `Status` options are "Active, Archived, Finalizing"; "Finalizing status will kick out users who are currently in the Session, and prevent changes from being made to Session Files or Markups. Read-only operations can still be used (such as downloading files or creating a Session File Snapshot)." — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- Snapshot: `POST .../files/{id}/snapshot` starts a job; `GET` the same path until `Status` is `Complete` or `Error` (other values `NoSnapshot`, `Requested`, `InProgress`); response has `DownloadUrl`, `LastSnapshotTime`, `StatusTime`. "While in a Session, PDFs and markups are stored separately. A Snapshot combines the PDF content with the markup layer into a single PDF so that the markups are viewable on the PDF outside of the Studio Session." — [Studio Session Guide](https://support.bluebeam.com/developer/studio-session-guide.html)
- "Password protected documents, documents with complex javascript, or documents with errors in them may not work" for snapshots. — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- Close-out: `DELETE /publicapi/v1/sessions/{id}`. — [Studio Session Guide](https://support.bluebeam.com/developer/studio-session-guide.html)
- `SessionDto` includes `InviteUrl`, `Status`, `ExpirationDate`, `SessionEndDate`, `OwnerEmail`, `Restricted`, `Version`. — [Developer Portal API docs](https://developers.bluebeam.com/docs)

**Projects details**
- Project file upload mirrors the Session pattern: "Create metadata for a new project file. PUT actual file to UploadUrl returned in a create response. POST confirm-upload at the end of file upload to make it available in a project." File metadata "Includes DownloadUrl which can be used to download file content." — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- Check-out/in: `POST .../checkout` ("Checkout file for modification"), `DELETE .../checkout` ("Revoke file checkout. This will put the file in a conflicted state in Revu if there are local changes."), `POST .../checkin` then `confirm-checkin`. `checkout-to-session` links a Project file into a Session ("Session must exist and not be linked to any other Project"), and `POST sessions/{sessionId}/files/{id}/checkin` updates the Project copy with Session changes. — [Developer Portal API docs](https://developers.bluebeam.com/docs)

**Webhooks**
- "Webhooks are a standard capability in the Bluebeam API and available to all integrations." Subscribe with `POST /publicapi/v2/subscriptions` body `{sourceType: "session"|"project", resourceId, callbackURI}`; "callbackURI must be a valid URI using https". `DELETE` "Sets a subscription's status to 'disabled'". All endpoints require the Authorization header and a `client_id` header. — [Optimize your integrations with Webhooks](https://support.bluebeam.com/integrations/use-webhooks.html)
- Events: Session level — Update (rename, update expiration date, finalize), Delete; Session document level — Create, Delete. Project level — Update (rename), Delete; Project item level — Create, Update (move, rename, check in), Delete. — [Webhooks](https://support.bluebeam.com/integrations/use-webhooks.html)
- Callback payload fields: `Source` ("Studio"), `ResourceID`, `ResourceType` (e.g. `SessionDocuments`, `Sessions`, `ProjectItems`, `Projects`), `Timestamp`, `User`, `EventType` (Create/Update/Delete), `IdPath`, `Path`, `ItemType`, `Name`. — [Webhooks](https://support.bluebeam.com/integrations/use-webhooks.html)

**OAuth 2.0**
- "All API calls are made under the context of a user." Only two grant types are supported: Authorization Code and Refresh Token. — [Get started](https://support.bluebeam.com/developer/getting-started-dev-portal.html)
- Authorize: `GET https://api.bluebeam.com/oauth2/authorize` with `response_type=code`, `client_id`, `redirect_uri` (must be one registered on the app), `scope` (space-separated), `state`. Token: `POST https://api.bluebeam.com/oauth2/token`, form-encoded, `grant_type=authorization_code`, `code`, `client_id`, `client_secret`, `redirect_uri`, `scope`. — [Authentication Guide](https://support.bluebeam.com/developer/authentication-guide.html)
- "Use Authorization Code authentication only when your App can keep a secret (for example, if the App runs on a web server that you control). Make sure to treat the client_secret as you would treat a password." — [Authentication Guide](https://support.bluebeam.com/developer/authentication-guide.html)
- Scopes table: `read_prime` (read-only access to a user's Studio Projects and Sessions for reporting), `full_user` (full access to user-owned Studio Projects and Sessions), `jobs` (automated Jobs in Studio Projects), `offline_access` (to receive a refresh_token). — [Authentication Guide](https://support.bluebeam.com/developer/authentication-guide.html)
- The same page's example request uses `scope=full_prime offline_access jobs` while its example token response shows `"scope":"full_user offline_access"` — the scope names are inconsistent inside Bluebeam's own guide. — [Authentication Guide](https://support.bluebeam.com/developer/authentication-guide.html)
- Lifetimes: authorization code 5 minutes; access token 60 minutes (`expires_in: 3600`, token type Bearer, "make sure the 'B' in 'Bearer' is capitalized"); refresh tokens rotate on every use and "expire if they are not used at least once every 7 days"; refresh tokens can be revoked. — [Authentication Guide](https://support.bluebeam.com/developer/authentication-guide.html)
- Refresh call: `POST /oauth2/token` with `grant_type=refresh_token`, `refresh_token`, and header `Authorization: Basic base64(client_id:client_secret)`. — [Authentication Guide](https://support.bluebeam.com/developer/authentication-guide.html)
- The OpenAPI token-request schema marks `client_id`, `client_secret` and `grant_type` as required and also defines an optional `code_verifier` ("must be 43 characters in length"); the docs' built-in OAuth panel defaults to "Use PKCE: no", "Credentials Location: body". Security schemes declared: `bearerAuth` (HTTP bearer, JWT) and `client_id` (apiKey in header). — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- Redirect URIs: entered at app creation, comma-separated, multiple allowed; Postman testing uses `https://oauth.pstmn.io/v1/callback`; to use the docs' Test Request, add `https://developers.bluebeam.com/docs`. Examples in the docs use `http://myserver.com` and `http://localhost:3000`. — [Get started](https://support.bluebeam.com/developer/getting-started-dev-portal.html); [Developer Portal API docs](https://developers.bluebeam.com/docs)
- App registration fields: name (≤90 chars), description (≤300 chars), region, redirect URL(s); result is a Client ID and Client Secret shown on the app page. — [Get started](https://support.bluebeam.com/developer/getting-started-dev-portal.html)

### Inferences
- **A browser SPA cannot hold the integration on its own; a SPA plus a serverless backend (e.g. Supabase Edge Functions) fits the documented flow.** Reasoning: the token endpoint requires `client_secret` for both code exchange and refresh, and Bluebeam says to use the flow only where the app "can keep a secret". The backend function would (a) receive the redirect, (b) exchange the code, (c) store the rotating refresh token encrypted, (d) refresh at least once every 7 days per connected user (each refresh returns a new refresh token that must replace the old one), and (e) proxy API calls adding the `Authorization: Bearer` and `client_id` headers. Webhook `callbackURI` must be HTTPS, which an Edge Function URL satisfies.
- PKCE appears to exist as an optional field (`code_verifier`) but nothing found says a public client can omit the secret, so a secret-less SPA flow should be assumed unavailable until Bluebeam confirms otherwise.
- Because an app is tied to one regional host, a product serving UK users would register a UK app against `https://api.bluebeamstudio.co.uk`; serving users whose BBIDs live on the US server would need a second app.
- During development only the developer's own BBID can sign in (Sandbox). Any pilot with real colleagues or clients needs production approval first, and Sandbox must not process live end-user data.
- The minimum cost of entry is one paid Bluebeam seat on Core or above (needed for portal access and to host Sessions); beyond that no API charge was found, but absence of a published fee is not proof that partner distribution is free.
- The portal previously ran on a Salesforce/MuleSoft-style stack (legacy links such as `developers.bluebeam.com/s/my-apps` and a "MuleSoft branded email" side-effect are still mentioned in the guides), so older tutorials and screenshots may not match the current UI.

### Gaps
- **Numeric rate limits** (Sandbox or Production): the Terms point to "Developer Documentation", but no figures appear on any page readable without login. The only numbers found are self-declared placeholders on a third-party site.
- **CORS behaviour** of the API hosts and of the pre-signed AWS upload URLs (i.e. whether a browser could `PUT` a PDF straight to `UploadUrl`): not documented.
- Whether **redirect URIs must be HTTPS** or may be `http://localhost` in production: examples show http, no rule stated.
- Which scope names are actually accepted (`full_prime` vs `full_user`; whether `read_prime` suffices for reading markups; whether v2 Markups or Webhooks need a specific scope): Bluebeam's guide contradicts itself.
- Criteria used in **production approval**, and the contents of the **Bluebeam Developer Network Branding Guidelines** (available only "by email request to integrations@bluebeam.com").
- Contents and cost of a **Partner Integration Agreement**, NFR licences, and any marketplace listing requirements: not public.
- Maximum file size for Session/Project uploads via API, and Session limits (files, attendees) as enforced through the API: not stated in the developer docs read.
- Whether webhook callbacks are signed or carry a shared secret for verification: not documented on the Webhooks page.
- No "Bluebeam Cloud API" for the web/mobile app's punch, RFI or submittal data was found; the Developer Portal documents Studio only.

## 2. Can markups be read or written through the API, or only whole PDFs? The practical round-trip

### Takeaway
Markups in a live Studio Session can be **read as structured JSON** (summary and full geometric/appearance detail) and their **status can be changed**, but there is no endpoint that creates, edits or deletes an individual markup. Writing markups is only possible indirectly: put annotations into the PDF before upload, or run the Project `importmarkups` job from a markup file. The documented PDF round-trip (create Session → upload → invite → finalise → snapshot → download) is fully supported.

### Cited Findings
- Marketing description of the three developer capabilities: "Sessions Roundtrips – ... launch Studio Sessions and invite collaborators directly from your app"; "Webhooks – ... subscribe to Studio updates"; "Markups APIs – Use the markups endpoints to access and update markup status from your app". — [Apps and Integrations](https://www.bluebeam.com/product/integrations/)
- `GET /publicapi/v2/sessions/{sessionId}/files/{fileId}/markups` returns a list whose items (`SessionMarkupDto`) carry: `markupId`, `name`, `parentName`, `type`, `subject`, `label`, `comments`, `status`, `layer`, `lock`, `displayName`, `email`, `created`, `modified`, `pageNumber`, `x`, `y`, `documentId`, `documentWidth`, `documentHeight`, `sessionId`, and measurement fields `length`, `unit`, `precision`, `scaleRatio`, `conversionFactor`. — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- `GET .../markups/details` (paged with `offset`, `limit`) returns `SessionMarkupDetailDto` items with roughly 90 properties, including: `type`, `subject`, `author`, `contents`, `richContents`, `creationDate`, `modDate`, `state`, `stateModel`, `rect`, `points`, `vertices`, `path`, `gestures`, `quads`, `callout`, `calloutMulti`, `strokeColor`, `fillColor`, `opacity`, `fillOpacity`, `width`, `dash`, `lineStyle`, `lineEnding`, `arrowBegin`, `arrowEnd`, `borderEffectStyle`, `borderEffectIntensity`, `pattern`, `blendMode`, `rotation`, `textFont`, `textSize`, `alignment`, `intent`, `shape`, `measure` (object), `cutouts`, `cutoutsPaths`, `doCaption`, `captionOffset`, `image`, `attachments`, `snapshot`, `ap`, `lock`, `hidden`, `print`, `readOnly`. — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- `PUT .../markups/{markupId}/status` takes `{Model, State}`; valid values come from `GET .../files/{fileId}/statuses`. — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- The OpenAPI document contains **no POST, PUT (other than status) or DELETE operation on Session markups**. — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- For files in Studio **Projects**, asynchronous jobs exist: `markuplist` ("Creates a job that will generate the list of the markups from the Pdf file"; result items `MarkupDto` = `Id`, `Type`, `Subject`, `Comment`, `Author`, `Status`, `Layer`, `Space`, `Page`, `X`, `Y`, `Width`, `Height`, `Rotation`, `Color`, `ColorFill`, `ColorText`, `LineStyle`, `LineWidth`, `Opacity`, `OpacityFill`, `Locked`, `Grouped`, `Checked`, `Parent`, `DateCreated`, `DateModified`, `ExtendedProperties`), `exportmarkups` ("Exports the Pdf file markups to an output file"; body `OutputFileName`, `OutputPath`, `Priority`, `CurrentPassword`), `importmarkups` ("Imports the markups from a list of files into the input Pdf file"; `Options.FileIDs[]`), `exportcustomcolumns` (".xml file"), `importcustomcolumns` ("overwriting any existing Custom Columns"), `flatten` (per-type options and `Recoverable`), `unflatten`, `stamp`. — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- The `jobs` OAuth scope is described as "Access automated Jobs in Studio Projects". — [Authentication Guide](https://support.bluebeam.com/developer/authentication-guide.html)
- Round-trip steps and the statement that a Snapshot "combines the PDF content with the markup layer into a single PDF". — [Studio Session Guide](https://support.bluebeam.com/developer/studio-session-guide.html)
- Webhooks fire on Session document create/delete and Session update/finalise/delete — there is **no markup-level event** in the published event table. — [Webhooks](https://support.bluebeam.com/integrations/use-webhooks.html)
- Real integrations follow exactly this pattern: Procore's Submittals integration creates a Session from attached PDFs, invites approvers, and "the Session is Finalized directly within Procore, pulling the marked-up PDFs back into the Submittal in Procore." — [Procore Submittals listing](https://integrations.bluebeam.com/apps/procore-submittals/)

### Inferences
- **Recommended round-trip for a web canvas app:** export board/sheet as a (non-PDF/A, unencrypted) PDF → `POST sessions` → `POST sessions/{id}/files` → `PUT` to `UploadUrl` within 10 minutes → `confirm-upload` → `invite`/`users` → subscribe a webhook on the Session → while open, poll `v2 .../markups` and `.../markups/details` to mirror comments/status into the app → on "finalise": `PUT sessions/{id}` with `Status: Finalizing` → `POST .../snapshot` → poll `GET .../snapshot` → download `DownloadUrl` → optionally `DELETE` the Session.
- Because no webhook fires per markup, near-real-time markup sync requires polling the v2 markups endpoints; polling cadence will be bounded by the unpublished rate limits.
- The detail DTO exposes enough geometry (`rect`, `vertices`, `points`, `path`, colours, line style, `measure`) to redraw Bluebeam markups natively on a web canvas without parsing the PDF — but only for files that are in a Session.
- To push app-authored markups *into* Bluebeam, the dependable route is to write them as standard PDF annotations in the uploaded PDF (see section 6). The Project `importmarkups` job is a second route but its accepted file types are not specified in the public spec.
- The snapshot PDF most likely keeps markups as live (editable) annotations rather than flattened content, because flattening is a separate, explicit job/option (`flatten`, shared-link `Flatten`) — but this is not stated outright.

### Gaps
- The JSON shape of the `measure` object, of `ExtendedProperties`, and the coordinate system/units of `x`, `y`, `rect` (PDF points vs. page fraction; origin) are not described in the spec.
- Output format of `exportmarkups` (.bax, .fdf, XML?) and accepted input formats for `importmarkups`: not specified.
- Whether custom-column values are included in either markups endpoint: no explicit field; unknown.
- Whether the v2 markups endpoints work after a Session is set to Finalizing (the status text says read-only operations still work, but markups are not named).
- No confirmation of whether snapshot PDFs preserve Bluebeam-specific data (custom columns, layers, measurement scale) identically to a "Save As" from Revu.

- Embedding Bluebeam's web UI in an iframe is both technically unsupported (nothing documented) and contractually discouraged ("frame" is listed in the Acceptable Use Policy).
- The in-PDF JavaScript API is a document-automation feature for Revu desktop, not an integration channel for a hosted web app; it does show Revu supports FDF import/export of annotations programmatically.

### Gaps
- The exact, officially documented format of `InviteUrl`, of the `studio://` handler, and of the web join link was not found on a Bluebeam-authored page (only user-written examples).
- Whether Bluebeam on web sets headers that block iframing was not tested (no login or probing was performed).
- No Bluebeam-published desktop plug-in SDK or command-line/script reference was located in this session beyond the PDF JavaScript reference.

## 6. File-level interoperability without the API

### Takeaway
Bluebeam markups are standard PDF annotations carrying extra Bluebeam-private keys, so a third-party tool that writes ordinary ISO 32000 annotations will show up in Revu, while Bluebeam-only data (custom columns, layers-by-name, slope/pitch, scale) will be ignored by other viewers. Bluebeam's side formats — `.bax` markups, `.btx` tool sets, `.bpx` profiles, custom-column `.xml` — are undocumented XML containers in which payloads are hex-encoded zlib streams wrapping raw PDF annotation dictionaries; community tools and one open-source project already read or generate them.

### Cited Findings

**Markups inside the PDF**
- A PDF produced with Revu shows a line markup stored as a normal annotation object (`/Type/Annot /Subtype/Line /L[...] /BS<<...>> /C[...] /Rect[...] /AP<<...>> /NM(...) /IC[...] /Subj(Beam) /M(...)`) with extra keys `/BSIColumnData[ ... ]` (an array of strings, one per custom column), `/SlopeType 0` and `/PitchRun 12`. — [pypdf discussion #2270](https://github.com/py-pdf/pypdf/discussions/2270)
- The custom-column definitions live in a separate PDF array object whose entries look like `<</Subtype/Text|Number|Formula|Choice /Name(...) /DisplayOrder n /Format/Normal /Precision n /Expression([Length] * [WeightData] * [Quantity]) /Items ... /DefaultValue(...) /AllowCustom false /Totals false /Deleted true>>`. — [pypdf discussion #2270](https://github.com/py-pdf/pypdf/discussions/2270)
- The pypdf maintainer could not find `BSIColumnData` in the PDF 1.7 or 2.0 references: "I think this is a private datafield that can be analysed only by specific viewers." — [pypdf discussion #2270](https://github.com/py-pdf/pypdf/discussions/2270)
- A decoded Tool Chest callout shows these keys on a FreeText annotation: `/DA(1 0 0 rg /Helv 10 Tf)`, `/IT/FreeTextCallout`, `/DS(font: Helvetica 10pt; text-align:left; margin:0pt; line-height:11.5pt; color:#FF0000)`, `/RD[...]`, `/CL[x1 y1 x2 y2 x3 y3]`, `/LE/OpenArrow`, `/FillOpacity 0.8`, `/Subj(Callout)`, `/BSIColumnData[(Electrical)()()()()]`, `/OC(Electrical)` (the layer name, "will be created if it isn't already in the PDF file"), `/TempBBox[...]`. — [UChapter2 forum: Tool for Decoding Bluebeam Configuration and Markup Files](https://uchapter2.com/brainery/tips-tricks/forum/topic/tool-for-decoding-bluebeam-configuration-and-markup-files/)
- Bluebeam's own Session-markup API schema names the data it keeps per markup: `subject`, `label`, `layer`, `status`/`state`/`stateModel`, `measure`, `scaleRatio`, `conversionFactor`, `unit`, `precision`, `cutouts`, `doCaption`, `captionOffset`, `borderEffectStyle`, `pattern`, `blendMode`, and so on. — [Developer Portal API docs](https://developers.bluebeam.com/docs)
- ISO 32000-1 (PDF 1.7) Table 178 gives polygon and polyline annotations an optional `/IT` intent whose values include `PolygonCloud`, `PolyLineDimension` ("intended to function as a dimension") and `PolygonDimension`, and an optional `/Measure` entry: "A measure dictionary (see Table 261) that shall specify the scale and units that apply to the annotation." — [ISO 32000-1 text as reproduced in the pdf_oxide repository](https://github.com/yfedoseev/pdf_oxide/blob/08accb2e0be8252309083a33fafc74015269594c/docs/spec/pdf.md)
- Two independent projects that write measurements for Bluebeam users both state that Bluebeam's own encoding is undocumented and that they had **not verified the result in Revu**: one PDF-export feature writes "Area → Polygon `/IT /PolygonDimension`, length → Line `/IT /LineDimension` ..., multi-leg → PolyLine `/IT /PolyLineDimension`, each with a `/Measure` RL dictionary (ISO 32000-1 §12.9...)" and notes "Bluebeam publishes no dictionary documentation for its measurement markups ... so this follows the PDF standard Acrobat writes", "Grouped-FreeText fallback is the next step if Bluebeam doesn't draw from `/Measure`", "Not checked: Bluebeam" (Oct 2026). — [planyr pull request #2448](https://github.com/mikeab7/planyr/pull/2448)
- An OpenRevu-fork work item titled "Bluebeam Revu interop: read and write standard /VP and /Measure scales and measurements" lists as background (flagged "verify against real files"): page `/VP` viewport arrays with `/BBox` and `/Measure`; a `/Measure` dictionary of `/Subtype /RL` with `/R` ratio text and `/X`, `/Y`, `/D`, `/A` number-format arrays (conversion factor `/C`, unit `/U`); "Revu adds proprietary keys on top. Inspect real Revu output before relying on anything"; sample Revu files "need a human with Revu". — [openrevu fork issue #12](https://github.com/mdouglass95/openrevu/issues/12)
- The PDF standard defines measurement properties as page viewports each holding a measure dictionary that maps user space to real-world distances (ISO 32000-1 §12.9). — [pdfboss-core docs (search-result excerpt only)](https://docs.rs/pdfboss-core); [ISO 32000-2 clause 12 errata index (search-result excerpt only)](https://pdf-issues.pdfa.org/32000-2-2020/clause12.html)

**Import/export of markups**
- Markups List > Import "Takes the markups from a PDF, XML, or [BAX] file and includes them in the active PDF"; "FDF files containing annotations generated from other PDF applications may also be imported." Export "Exports all markups to a [BAX] or FDF file. The BAX file can be imported into another PDF ... The BAX file can also be imported into Excel. Markups can also be exported to the FDF format for interoperability with other PDF applications." — [Markups List (Revu 21 help)](https://support.bluebeam.com/online-help/revu21/Content/RevuHelp/Menus/Window/Panels/Markups/Markups-List--MTV.htm); [Markups List (user manual)](https://support.bluebeam.com/user-manual/menus/window/markups-list.html)
- Transfer workflow: Markups List > Markups > Export Markups, "Save the Bluebeam Annotations (.bax) file", then import into the destination document. — [Transfer markups to another document](https://support.bluebeam.com/revu/how-to/transfer-markups.html)
- Markup **Summary** output types: CSV, XML, PDF or Print; "For Revu 21 users with a Basics subscription, the only available output type is PDF." — [Markup summary](https://support.bluebeam.com/user-manual/menus/batch/summary.html)
- User testing (2023): a Summary XML is **not** re-importable as markups ("When exporting a 'summary', it will not store the same data as if you were to actually 'Export markups'"); a real markups export can be saved with an `.xml` extension and re-imported; "if you export .bax, then open the file with notepad, you will see the same format as if you saved xml". — [UChapter2 forum: Markups XML Import](https://uchapter2.com/brainery/tips-tricks/forum/topic/markups-xml-import/)
- The Studio API offers server-side equivalents for Project files: `exportmarkups`, `importmarkups`, `markuplist`, `exportcustomcolumns` (.xml), `importcustomcolumns`, `exportformdata` (.xml, .csv or .fdf). — [Developer Portal API docs](https://developers.bluebeam.com/docs)

**Flattening**
- "Whenever you flatten markups, Revu merges them into the content layer of the PDF. After this process, changing or modifying your markups is impossible, and they'll no longer appear in the Markups list." Unflatten works per page only if "Allow Markup Recovery" was enabled, and recovery is destroyed by Edit Text, Search and Replace, Erase Content, Cut Content, Reduce File Size, Apply Redactions, Color Processing, Repair PDF. "Flattened Form Fields cannot be unflattened under any circumstances." "Flattening ensures markups and annotations will display in PDF viewers and mobile apps that only display PDF content." — [Locking vs. flattening markups](https://support.bluebeam.com/revu/features/locking-vs-flattening-markups.html)
- The API `flatten` job exposes per-type switches (Ellipse, FileAttachment, Flags, FormFields, Group, Image, InkAndHighlighter, LineAndDimension, MeasureArea, Notes, PolygonAndCloud, Polyline, Rectangle, Snapshot, Stamp, TextAndCallout, TextMarkups), a `LayerName`, and `Recoverable`. — [Developer Portal API docs](https://developers.bluebeam.com/docs)

**Side-car formats**
- Extensions and meanings reported by a community decoder: `btx` – Tool Chest group; `bpx` – Profile; `blx` – Linetypes; `bhx` – Hatches; `bax` – Markups. — [UChapter2 decoder thread](https://uchapter2.com/brainery/tips-tricks/forum/topic/tool-for-decoding-bluebeam-configuration-and-markup-files/)
- `.btx` is XML; a tool looks like `<ToolChestItem Version="1"><Name>…16 uppercase letters…</Name><Type>Bluebeam.PDF.Annotations.AnnotationFreeText</Type><Raw>…PDF annotation dictionary…</Raw><X>…</X><Y>…</Y><Index>…</Index><Mode>properties</Mode></ToolChestItem>`; values are hexadecimal text beginning `789c`, i.e. zlib-compressed; "zlib compression often gives a different result even if you didn't edit anything. In all of my testing, this didn't matter to Bluebeam"; `<Mode>` is `properties` or `drawing`; `.bpx` contains an `<Icon>` that is a PNG; "stream" sections contain non-printable bytes and break if edited; the author had "only decoded about half of the structured text in the `<Raw>` portions". (Posts dated Sept 2024.) — [UChapter2 decoder thread](https://uchapter2.com/brainery/tips-tricks/forum/topic/tool-for-decoding-bluebeam-configuration-and-markup-files/)
- Independent confirmation: ".btx ... it's XML based and the values are zlib encoded" (unanswered question, Oct 2025). — [Stack Overflow 79786972](https://stackoverflow.com/questions/79786972/bluebeam-btx-toolchest-syntax)
- A user building a product on programmatic tool-set generation: "These toolboxes can be edited programmatically but it's…complicated ... you kind of have to do a deep dive into understanding the encoding, the bluebeam custom columns infrastructure and the PDF file format." (June 2025) — [Bluebeam Community discussion 5593](https://community.bluebeam.com/discussion/5593/creation-manipulation-of-bluebeam-tools-using-the-btx-file-code-xml-structure)
- OpenRevu (open source, AGPL-3.0-or-later per a third-party catalogue) imports `.btx` tool sets (shapes, lines, arrows, clouds, pens, text boxes, callouts, notes; not stamps) and states: "The `.btx` format is not documented by Bluebeam. OpenRevu reads it from the description of the Bluebeam community ... It has not been checked against files from every Bluebeam version"; it does not read `.bpx` or `.bax`; it declares "OpenRevu is not connected to Bluebeam, Inc."; "A markup is a standard PDF annotation. Other PDF viewers can show it. OpenRevu stores its own data (measurement values, scales, and review status) in custom keys. Other viewers ignore these keys." — [vineetpadia/openrevu](https://github.com/vineetpadia/openrevu); [remade.wiki comparison](https://remade.wiki/software/bluebeam-revu/)
- Tool sets are exported/imported/shared as `.btx` files (also by drag-and-drop into Revu; shareable from a network drive); profiles are exported/imported as `.bpx`. — [Share tool sets](https://support.bluebeam.com/revu/how-to/share-tool-sets.html); [Import and export profiles (search-result excerpt only)](https://support.bluebeam.com/user-manual/menus/revu/import-export-profile.html)
- **`.bex`** is the Sets file: "Sets are saved with the file extension: .bex"; a Set "can load multiple PDFs in Revu as if they were one document" (Core, Complete or Max plans). — [Sets Panel, Revu 20 help (search-result excerpt only)](https://support.bluebeam.com/online-help/revu20/Content/RevuHelp/Menus/Window/Panels/Sets/Sets-Tab--V.htm); [Manage large PDFs with Sets (search-result excerpt only)](https://support.bluebeam.com/revu/how-to/manage-large-pdfs-with-sets.html)
- Custom-column Choice items can be imported from CSV (column A item name, B subject, C numeric value). — [Create and manage columns in the Markups list](https://support.bluebeam.com/user-manual/menus/window/custom-columns.html)

**Compatibility with other PDF tools (limited evidence)**
- A US state DOT guide notes that status changes made in Bluebeam appear in Adobe ("When the comment status is changed to 'Accepted' by the Reviewer, a green box with a thumbs-up will appear in Adobe") and that for Adobe compatibility responses must be entered as a Reply rather than in Bluebeam columns ("Rather than use the columns to document responses, each comment/disposition ... must be in a 'Reply' to display correctly within Adobe"). — [ODOT Bluebeam Review Guide](https://dam.assets.ohio.gov/image/upload/transportation.ohio.gov/cadd-mapping/bluebeam-review-guide.pdf)
- Revu 20 "is no longer supported as of July 31, 2026" with end of life "effective December 31, 2026" — relevant when choosing which Revu versions' file behaviour to test against. — [Bluebeam Revu support home (search-result excerpt only)](https://support.bluebeam.com/revu/revu.html)

### Inferences
- **Could a third-party app generate a `.btx` tool set?** Yes, technically: it is XML whose `<Raw>` payload is a PDF annotation dictionary, zlib-compressed and hex-encoded; a community decoder, an open-source importer, a commercial hobby product and a Bluebeam-hosted Claude skill all do it. Risk: the format is undocumented, version-dependent and partially understood, so generated files need testing in current Revu.
- **Could a third-party app read a Markups List XML/CSV summary?** Yes — it is a plain export meant "for use in Excel or other programs" — but it is a report, not a lossless markup container; for lossless transfer use the PDF itself, `.bax`, or FDF.
- **Safest write path into Bluebeam:** emit standard ISO 32000 annotation subtypes (Text, FreeText incl. `/IT /FreeTextCallout`, Line, Square, Circle, Polygon, PolyLine, Ink, Highlight, Stamp) with `/Subj`, `/T` (author), `/Contents`, `/M`, `/NM`, `/C`, `/IC`, `/CA`, `/BS`, appearance streams, and review state via reply annotations. Since Revu itself serialises markups with these keys, it will list them in the Markups List. Bluebeam-specific enrichment (`/BSIColumnData`, `/OC(layer)`, slope/pitch keys) is optional and private.
- **Measurements:** Bluebeam keeps scale/unit/precision per markup and per page; whether Revu honours a standard `/Measure` dictionary and `/VP` viewport written by another tool (and whether it writes them itself) could not be confirmed. The standards-based encoding to try first is Polygon `/IT /PolygonDimension`, PolyLine `/IT /PolyLineDimension` and Line `/IT /LineDimension`, each with a rectilinear `/Measure` dictionary, plus a page `/VP` viewport. A cautious design also carries the measured value in the comment/label text and in the appearance stream, and expects that a user may need to re-apply scale in Revu.
- Status values (Accepted, Rejected, Cancelled, Completed, None) map onto the standard PDF Review state model replies, which is why Adobe shows them; custom columns do not travel.
- After flattening, only the visual appearance survives — no Markups List entries, layers-as-annotations, custom columns or editable measurements — unless "Allow Markup Recovery" was used and none of the listed destructive operations has run.

### Gaps
- No authoritative (Bluebeam-published) specification exists for `.bax`, `.btx`, `.bpx`, `.blx`, `.bhx` or the private annotation keys; everything above is community reverse-engineering.
- **`.bex`** internal structure (it is the Sets configuration file) was not examined; no description of its contents was found.
- **XFDF**: Bluebeam's help pages read mention FDF only; XFDF import/export support could not be confirmed.
- **Unverified, and the most important open technical question:** whether Revu reads a standard `/Measure` dictionary and `/VP` viewport scale written by another tool, recalculates from it, or needs its own private keys. Two third-party projects write the standard form for Bluebeam users but both say they have not checked the result in Revu. Closing this needs a hands-on test in a licensed copy of Revu.
- No write-up was found that catalogues Bluebeam's private keys for **measurements, calibration/scale, Spaces, count markups or groups**. A second follow-up search (25 Nov 2026) again found none.
- Sources disagree on which standard edition puts `/Measure` directly on an annotation: the ISO 32000-1 table quoted above includes it for polygon/polyline annotations, while one community note says a `/Measure` key on a line or polygon annotation "is PDF 2.0 (ISO 32000-2) or an Adobe extension, not 32000-1" ([openrevu fork issue #12](https://github.com/mdouglass95/openrevu/issues/12)). The ISO text is the better authority; the original ISO document was not opened directly.
- No systematic, sourced test matrix of which third-party annotation types/appearances Revu preserves on open, edit and save was found.

## 7. BIM and open-standard routes (BCF, IFC, 3D PDF, ISO 19650)

### Takeaway
Bluebeam's BIM handling is 3D-PDF-centric: Revu converts IFC or U3D files (and Revit/Navisworks/AutoCAD/SolidWorks via plugins) into 3D PDFs with a model tree and metadata. No native BCF import/export in Bluebeam was found; where BCF appears it is produced by the partner application (Vectorworks) from Bluebeam markups. No Bluebeam statement on ISO 19650 naming or metadata was found.

### Cited Findings
- 3D PDFs can be created by dragging "Universal 3D (*.u3d) or Industry Foundation Classes (*.ifc)" files into Revu, or with Bluebeam plugins for AutoCAD, SolidWorks, Revit and Navisworks (SketchUp Pro plugin is Revu 20 only). Available in Revu 21 with a Core, Complete or Max plan (Revu 20: CAD or eXtreme edition). Features: 3D Model Tree, sorting/editing 3D metadata, saved Views, filtering, "Export to CSV Summary", and adding 3D content to an existing 2D PDF. — [3D PDFs](https://support.bluebeam.com/revu/features/3d-pdfs.html)
- "3D Annotation JavaScript is not supported by Revu." — [Revu JavaScript Doc object](https://support.bluebeam.com/developer/javascript/doc.html)
- Vectorworks' Bluebeam Connection lets users "import markups back into your Sheet Layers or convert them into BIM Collaboration Format (BCF) issues"; the directory listing mentions "managing BCF issues ... all within Vectorworks". — [Vectorworks newsroom](https://www.vectorworks.net/en-US/newsroom/bluebeam-integration); [Vectorworks listing](https://integrations.bluebeam.com/apps/vectorworks/)
- Archicad's connection turns Bluebeam annotations "into Archicad issues". — [Graphisoft listing](https://integrations.bluebeam.com/apps/bluebeam-studio-connection/)
- Bluebeam holds patents on linking 2D sheets to 3D models and on annotations tied to 3D views (see section 8: US 11,468,208; 12,045,544; 8,823,744). — [USPTO Patent Public Search, assignee Bluebeam](https://ppubs.uspto.gov/pubwebapp/external.html?q=%28Bluebeam%29.as.&db=USPAT)
- The Studio API has file-property jobs (`fileproperties`, `fileproperty`, `filepropertyvalue`) for reading and setting PDF document properties on Project files, and conversion jobs `dwg2pdf`, `word2pdf`, `excel2pdf`, `image2pdf`, `ps2pdf`; there is no IFC or BCF job. — [Developer Portal API docs](https://developers.bluebeam.com/docs)

### Inferences
- For a tool that already views IFC, the realistic bridge to Bluebeam is **PDF, not BCF**: render sheets/views to PDF, round-trip through a Studio Session, then translate returned markups (from the v2 Markups JSON or the snapshot's annotations) into BCF topics **inside the tool**, exactly as Vectorworks and Graphisoft do. The markup's page coordinates would need a tool-side mapping back to model viewpoints.
- Offering BCF export/import and IFC-native issue pinning would be a genuine differentiator relative to Bluebeam, since nothing found shows Bluebeam doing either natively.
- ISO 19650 metadata could be carried into Studio Projects only as file names/folder structure and PDF document properties (via the file-property jobs); there is no dedicated field model.

### Gaps
- Absence of BCF in Bluebeam is inferred from not finding it in Bluebeam's 3D PDF page, API spec or directory text; no Bluebeam statement saying "BCF is not supported" was found.
- No Bluebeam documentation of ISO 19650 naming conventions, status/revision codes or CDE workflows was found.
- How much IFC property data survives into Revu's 3D model tree, and whether markups on 3D PDFs are exposed by the v2 Markups API, is unknown.

### Inferences
(These are the researcher's reading of the sources, offered to help frame questions for a lawyer — not legal conclusions.)
- **The contract risk is larger than the patent or trademark risk for an API-using competitor-like product.** Anyone who accepts the Developer Terms (required to get credentials) or the GTC (required to use Revu/Studio) agrees not to access Bluebeam "in order to build a product using features, functions or graphics similar to" it, nor to "copy any features, functions or graphics", nor to use the API "to replicate or attempt to replace the user experience". A product that both integrates via the Studio API *and* offers Bluebeam-like markup, measurement, tool-library and session features sits squarely in the zone these clauses address, and Bluebeam controls production approval. This should be raised with counsel and probably with Bluebeam's integrations team before building on the API.
- Studying Bluebeam's `.btx`/`.bax` formats by examining files inside a licensed copy of Revu may fall within the GTC's reverse-engineering clause (§1.4) ("attempt to derive the ... underlying ideas"), subject to the carve-out "Except as permitted by ... applicable law" (interoperability exceptions vary by jurisdiction). Reading and writing **ISO-standard PDF annotations**, FDF, and user-exported CSV/XML summaries does not require examining Bluebeam software at all.
- **Generally lower risk:** independently implementing generic functional ideas (redlining, clouds, callouts, length/area/count measurement, calibration, a markup list with status and filters, saved tool presets, real-time co-editing) with original code, original icons, original layout and neutral names; interoperating through ISO 32000 annotations; nominative, accurate statements such as "exports PDFs that open in Bluebeam Revu" with a clear non-affiliation notice.
- **Higher risk:** using "Bluebeam", "Revu", "Studio" (as a product/feature name for collaborative PDF hosting — the registration's goods description is close to exactly that), "Batch Link", or lookalike logos in product or feature names; copying Bluebeam's icons, tool artwork, hatch/linetype libraries, stock tool sets or profiles; reproducing Revu's panel layout and visual design closely; redistributing Bluebeam-authored `.btx`/`.bpx` files; scraping or automating Bluebeam's web apps; implying endorsement.
- "Tool Chest" appears to be an unregistered (™) mark in the US: no live registration was found, but Bluebeam has used and claimed it for many years, so common-law/passing-off rights are possible; a neutral name ("tool library", "presets") avoids the question.
- Patent watch-list most relevant to a web markup/measure/collaboration tool: the thin-client and cross-device markup-synchronisation families (11,308,261 / 12,001,778 / 12,432,270; 11,599,325 / 12,079,535 — granted 2022–2025, so in force for many years), dynamic fill (10,452,751 / 11,087,069), legends with cumulative quantities (10,534,859 / 11,182,543 / 12,236,184), sequenced annotations (8,443,280), session recording/playback (11,132,165), raster-optimised shared rendering (10,402,472 / 11,120,197), batch link generation, sets, and 2D–3D linkage (11,468,208 / 12,045,544). Whether any planned feature falls within the **claims** requires a freedom-to-operate review; abstracts and titles are not the legal scope.
- The two 2005-filed palette patents (7,600,193 and 7,600,198) would ordinarily reach the end of a 20-year term around late 2025, possibly extended by patent-term adjustment; their current status should be verified before assuming they have expired.
- US patents and US trademark registrations do not by themselves apply in the UK; Bluebeam lists European patent counterparts (which may or may not be validated in the UK) and says its marks are registered "in the U.S. and other countries".

### Gaps
- **UK IPO and EUIPO trademark registers were not searched**; UK/EU registration status of BLUEBEAM, REVU, STUDIO and TOOL CHEST is unconfirmed.
- **Patent claims were not read** (only titles and ten abstracts), legal status/expiry/maintenance-fee status was not checked, and European/UK validation status of the listed EP patents was not checked. Pending applications (pre-grant publications) were not searched.
- The full GTC text was sampled through two extraction queries rather than read end-to-end, so other relevant clauses may exist. Note the mismatch to raise with counsel: a UK customer's GTC is under English law (Bluebeam Ltd. UK), whereas the Developer Terms are under California law with JAMS arbitration in Los Angeles regardless of the developer's location.
- The **Bluebeam Developer Network Branding Guidelines** are not public, so permitted wording/logo use for "works with Bluebeam" claims is unknown.
- The Product and Services Addendum, Data Processing Addendum and AI Transparency page were not read.
- No litigation or enforcement history concerning Bluebeam's patents, marks or API terms was researched.
